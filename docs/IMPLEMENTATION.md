# 구현 결정

## 기존 구조와 유지 범위

돌봄한눈은 정적 HTML·CSS·JavaScript와 Python 수집/생성 도구로 운영된다. 검색 인덱스는 `data/care`의 유형별 gzip JSON, 기관 상세·사진은 `data/nhis`의 기관별 파일이다. 이 구조에 맞추어 같은 형태의 치매 데이터 인덱스와 센터별 상세를 MASTER에 추가했다.

기존 페이지에는 독립 연결 스크립트 두 줄만 추가했다. 기존 지도·검색·공단 수집·길찾기 API는 수정하지 않았다. 치매센터 수집은 별도 워크플로로 분리해 공단 갱신 실패와 결합되지 않는다. 치매안심 frontend는 현재 별도 저장소에 작성했다.

## 데이터 계약

- `data/dementia/manifest.json`: `schemaVersion`, 통합 개수, 유형별 개수, 두 출처의 기준일·건수, 검색 파일·revision.
- `data/dementia/centers.json.gz`: 안정적인 `id`, 이름·별칭·유형·지역·주소·위치·프로그램 검색 태그.
- `data/dementia/details/{id}.json`: 연락처·공식 홈페이지·운영기관·프로그램 원문·필드별 출처·출처 간 차이.
- `data/sync-manifest.json`: MASTER 커밋·동기화 버전·전체 파일의 크기와 SHA-256. 이 파일만 소비 프로젝트에서 생성한다.

원본을 행 단위로 비교하여 원문 명칭과 모든 출처를 보존한다. 전화번호와 가까운 좌표가 일치하면 센터명의 표기 차이도 통합한다. 본소·분소는 혼합하지 않는다. 자료에 등록된 광역센터만 표시하며 모든 광역센터가 빠짐없이 들어 있다는 문구를 사용하지 않는다.

## 운영

MASTER 데이터 갱신 → MASTER 원격 반영 → 치매안심 Actions에서 MASTER 한 커밋 checkout → 전체 JSON 복사/해시 검증 → 정적 빌드 → Pages 배포 순서다. 자동 갱신을 시작하려면 두 저장소 원격 반영 및 GitHub Pages 설정이 필요하다. 두 저장소의 원격 반영은 MASTER부터 진행한다. DNS 변경과 Pages 활성화는 별도로 확인한다.

수집/동기화/빌드 중 필수 원본 누락·건수 오류·복사 중 변경·해시 불일치가 있으면 실패한다. 이전 배포에는 영향을 주지 않는다. 로컬의 수집 중인 MASTER 대신 수집 완료 상태나 고정된 Git checkout을 사용한다. 파생 자료를 양쪽 저장소에서 따로 편집하지 않는다.

## 확장

주변 돌봄기관의 내부 요약이 필요하면 현재 Origin의 `data/care/manifest.json`과 선택 유형 파일만 로드한다. 상세·사진은 선택 기관에 한정해 요청한다. 향후 검사/가족지원 데이터가 추가되어도 수집·정규화는 MASTER에만 추가하고 치매안심은 정적 JSON 소비자로 유지한다.

## 라이선스와 지도

Leaflet 1.9.4(BSD-2-Clause), Leaflet.markercluster 1.5.3(MIT)는 `public/vendor`에 고정하며 라이선스를 동봉한다. OpenStreetMap 타일에는 출처 표시를 유지하고 일반 브라우저 캐시를 사용한다. 외부 타일 로딩 실패 시 검색·상세는 유지하고 배경지도 오류를 표시한다.
